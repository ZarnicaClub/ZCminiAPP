# Макет CRM для Figma — как открыть, править и вернуть на внедрение

**Проект:** Zarnica CRM Mini App · **версия приложения:** v13.14 · **дата макета:** 05.10.2026
*(экраны сняты с версии 13.10; в 13.11–13.14 менялись записи звонков, теги и стрелки календаря — на макете этих правок нет)*
**Где лежит:** папка `figma/` репозитория ZCminiAPP, рядом с кодом фронта (`crm/templates/index.html`, `crm/static/app.js`, `crm/static/style.css`).

## 2. Как открыть в Figma

### Вариант А — SVG (рекомендую: без плагинов, без интернета, бесплатно)

1. Открыть новый файл в Figma.
2. Перетащить мышью все файлы из папки `svg/` на холст (или File → Place image).
3. Каждый файл встанет отдельным фреймом 390 × 844; внутри — слои, сгруппированные по именам классов.

### Вариант Б — HTML через плагин html.to.design

1. Figma → меню Plugins → найти **html.to.design** (by divRIOTS) → Run.
2. Во вкладке импорта выбрать загрузку **локального файла** и указать `ZC-CRM-maket.html`.
3. Плагин отрисует страницу и создаст редактируемые слои с авто-layout. На бесплатном тарифе — до 10 импортов в 30 дней, нам нужен один.
4. Если плагин просит URL и не принимает файл — использовать вариант А, он даёт тот же результат.

## 3. Как править

- Слои названы по классам из боевого CSS: `sch-card` (карточка расписания), `card` (заказ/клиент), `bso-card`, `call-card`, `dialog-body`, `bottom-nav`, `chip`, `month-arrow` и т. д. Это те же имена, что в коде — по ним правка потом однозначно ложится в стили.
- Текст — настоящие текстовые слои, редактируются как обычно. Шрифт в макете указан **Inter** (в приложении — системный шрифт телефона: `-apple-system / Segoe UI`). Если важна точная гарнитура — можно поменять на системную, метрики близкие.
- Эмодзи (📅 👥 📋 📞 🎯 🕒 🏕 🧾) — обычные символы текста. В Figma отображаются системным эмодзи-шрифтом; если у вас они не видны, включите в Figma показ эмодзи или замените на свои иконки.
- Цвета уже заданы в слоях. Палитра приложения:

| Токен | Значение | Где используется |
|---|---|---|
| `--bg` | `#f1f0e9` | фон экранов |
| `--card` | `#ffffff` | карточки, шапка навигации |
| `--text` | `#242720` | основной текст |
| `--muted` | `#73776d` | подписи, второстепенный текст |
| `--line` | `#dadbd3` | рамки, разделители |
| `--green` | `#708f3f` | активные кнопки, чипы, точка недели |
| `--green-dark` | `#435c27` | акценты, активный пункт меню |
| `--green-soft` | `#e7eddc` | бейджи, пилюли сумм |
| Пейнтбол | фон `#eef4e6`, полоса `#6f9a3f` | карточка расписания |
| Лазертаг | фон `#f7f1de`, полоса `#b9962c` | карточка расписания |
| Кидбол | фон `#f7e8e5`, полоса `#bd5a4c` | карточка расписания |

- Включать/выключать то, чего в приложении нет, не нужно: макет повторяет текущее состояние 1:1 (включая неактивные заглушки «＋ Новая запись» и «☷»).

## 4. Как вернуть правки мне

Два способа, оба рабочие:

1. **Ссылка на файл Figma + токен доступа.** В Figma: Settings → Security → Personal access tokens → создать токен с правами чтения файлов; ссылку дать с доступом «can view». Я читаю файл по REST API и забираю ваши правки.
2. **Экспорт изменённых фреймов.** Выделить фрейм → правая кнопка → Export → формат SVG (для правок геометрии и стилей) или PNG 2x (если просто «смотрится иначе»). Прислать файлы в чат.

Если правки текстовые — можно просто списком в чат: «на экране Заказы сделать чипы крупнее, убрать блок БСО из карточки».

## 5. Что происходит после

1. Я переношу правки в код: `crm/static/style.css`, `crm/static/app.js` (+ `index.html`, если меняется структура).
2. Прогоняю `python scripts/gen_webassets.py` — без этого в образ уедет старая вёрстка (ассеты вшиты в `crm/webassets.py`).
3. Проверяю вёрстку в headless Chrome на мобильном вьюпорте 390 × 844 и показываю скриншоты до/после.
4. Выкатываю релиз: новая версия в `VERSION` → GitHub Actions собирает образ → Docker Hub → переключение тега приложения ZCminiApp в Timeweb. Номер версии вы увидите в панели.

Напоминание: правки в Figma в приложение сами не попадают — Figma это черновик, в код переношу я.

## 6. Чем макет не является (честные ограничения)

- Это не интерактивный прототип: нажатия, переходы, скроллы и карусели в файле статичны. Логика экранов описана в `docs/web-ui-registry.md` и в коде.
- Анимации (нажатие карточки, появление диалога) не показаны — только визуальные состояния.
- Состояние «Загрузка…» и ошибки сети показаны не на всех экранах, чтобы не раздувать файл.
- Вёрстка зафиксирована для ширины 390 pt; для 360 и 430 pt в CSS есть отдельные правила, в макете они не отрисованы.
