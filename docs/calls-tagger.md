# calls-tagger: расшифровка новых звонков и разметка по словам

Служба рядом с `calls_worker`: воркер забирает записи из почты, а `calls_tagger`
берёт **новые** звонки, расшифровывает запись и проставляет теги.

## Что кладём и куда

Ничего нового не создаём: всё пишется в уже существующее поле `calls.metadata` (jsonb).

```json
{
  "tags": {
    "type": "корпоратив",
    "why": "корпоратив",
    "date": {"date": "2026-10-31", "kind": "explicit", "text": "31 октября"},
    "players": {"players": 30, "text": "30 человек"},
    "source": "rules-v3",
    "model": "whisper-small-int8",
    "tagged_at": "2026-10-10T16:20:00+00:00"
  },
  "transcript": "текст разговора одной строкой",
  "transcript_model": "whisper-small-int8"
}
```

Тип запроса: `недозвон`, `нецелевой`, `школьная_группа`, `детский`, `корпоратив`,
`праздник_взрослые`, `просто_игра`, `непонятно`. Порядок проверки — от явного к общему.
Правила лежат в `calls_tagger/tags.py` (чистые функции, покрыты `tests/test_calls_tagger.py`);
что изменила версия 13.14 — раздел «Правила v2» ниже.

## Почему только правила

Расшифровка приходит с ошибками («пиньболг» вместо «пейнтбол», «позаналы от платы»),
поэтому ищем **корни** слов, а не точные формы. Правила объяснимы: в `tags.why` видно,
по какой фразе приняли решение. Модель решений (Jev/Laya) — следующий шаг, когда
накопится разметка для проверки.

Ловушки, на которых правила уже спотыкались (закрыты тестами):
«дет» внутри «будет», «класс» внутри «классные перчатки», «в среднем» как будто среда,
«сегодня вам перезвоню» как дата игры, цена «3000 рублей с человека» как число игроков.

## Правила v2 (13.14, история — в прод не выкатывалась)

Первый прогон правил по живым звонкам (13.13) показал две дырки: автоответчики попадали в разметку
как разговоры, а «организация мероприятий» уходила в корпоратив. Что изменилось:

- **Новый тип `недозвон`** (проверяется первым): автоответчик, «оставьте сообщение», «абонент сейчас
  не может ответить», «номер занят/недоступен», «вне зоны доступа», «аппарат абонента выключен».
  Это не разговор с клиентом — дату и число игроков у таких звонков не ставим вовсе.
- **Корпоратив = заказ ОТ КОМПАНИИ**, а не слово «организация»: признаки — `фирм`, `юрлиц`, `ооо`,
  `безнал`, `по счёту/по счету`, `платёжное поручение`, `тендер`, `закупк`, `сотрудник`, `коллег`,
  `от работы`, `тимбилд`, `начальств`, `день компании`.
- **Новый тип `организатор`** — агентство/посредник: «организация мероприятий», «организатор праздников»,
  `агентств`, `event`. Но если у организатора группа **от 30 человек** (`CORP_FROM_ORGANIZER_MIN`),
  звонок всё равно становится `корпоратив` — так решил Артём 10.10.2026.
- **Вопрос про цену — это заявка:** «сколько стоит», «сколько будет стоить», «почём», «цена», «прайс»
  теперь относят звонок к `просто_игра`, а не к `непонятно`.
- **Мусорные звонки сузили:** в `нецелевой` больше не отправляет одно слово «предлагаем» (оно звучит
  и в обычной продаже) — только «по вопросу сотрудничества», «предлагаем свои услуги», «продвижение»,
  «маркетинг», «актуальные заявки».
- В `metadata.tags.source` теперь `rules-v2` — по этому полю видно, какой версией правил размечен звонок.

Порядок типов после v2: `недозвон` → `нецелевой` → `школьная_группа` → `детский` → `корпоратив` →
`организатор` → `праздник_взрослые` → `просто_игра` → `непонятно`.

Подписи и цвета новых типов добавлены в мини-апп (`CALL_TAG_LABEL` / `CALL_TAG_CLASS` в `crm/static/app.js`):
«Недозвон» — серый (`tag-miss`), «Организатор» — бирюзовый (`tag-agent`).

### Разовый прогон по истории

Флаги: `--once --since ГГГГ-ММ-ДД --until ГГГГ-ММ-ДД [--overwrite]`. `--overwrite` нужен после правки
словаря — иначе уже размеченные звонки пропускаются. Живую службу на время прогона останавливаем:
две расшифровки разом (~1,2 ГБ каждая) в 2 ГБ сервера не влезут.

```bash
systemctl stop zc-tagger
cd /opt/zcminiapp && set -a && . ./.env.worker && set +a
export TAGGER_MODEL_DIR=/opt/zcminiapp/models TAGGER_MODEL=small TAGGER_BATCH=100
/opt/zcminiapp/.venv-tagger/bin/python -m calls_tagger.main --once \
    --since 2026-10-01 --until 2026-11-01 --overwrite
systemctl start zc-tagger
```

Факт прогона 10.10.2026 (18:20–18:38 UTC, ≈18 минут): размечено **40 звонков**, все с `source=rules-v2`.
Разложилось так: детский 8, корпоратив 7, просто игра 7, **недозвон 6**, непонятно 5, праздник взрослые 3,
нецелевой 2, **организатор 1**, школьная группа 1. Замер: 36 звонков октября (1,1 ч аудио) — ≈17 минут;
весь архив (≈420 звонков, 13,9 ч аудио) — около 3,5 часов, платить за это не нужно (считает сервер).

## Правила v3 (версия 13.15)

Правки по замечаниям Артёма 11.10.2026 после просмотра живых звонков.

- **Тип «организатор» удалён совсем** — «бред какой-то»: агентство или посредник сам по себе
  тип не задаёт. Звонок идёт по остальным словам, а от **30 человек** становится корпоративом.
  Вместе с типом убраны подписи и цвета плашки в мини-аппе.
- **Корпоратив — заказ от компании ИЛИ большая группа.** Признаки компании (`фирм`, `юрлиц`, `ооо`,
  `безнал`, `по счёту`, `платёжное поручение`, `тендер`, `закупк`, `сотрудник`, `коллег`, `от работы`,
  `тимбилд`, `начальств`, `день компании`) работают как раньше; добавилось правило
  `CORP_MIN_PLAYERS = 30`: если названо от 30 человек и тип иначе вышел «просто игра» или «непонятно» —
  это корпоратив. Детские, школьные и «дни рождения» правило не перебивает.
- **Число игроков берём из слов заказчика, а не первое попавшееся.** Расшифровка приходит одной строкой
  (слова клиента и администратора не разделены), поэтому отбрасываем числа из служебных фраз:
  - пример расчёта администратора: «если вы ставите **на 2 участника**, то есть 30 человек»;
  - акции: «если **больше 16 человек** — коробка шаров в подарок»;
  - вместимость помещений: «беседка **до 35 человек**»;
  - тарифные минимумы: «**минимум 8 участников**», «тариф», «программа»;
  - цена и боеприпасы: «3000 рублей», «500 шариков/шаров», «**5 бое**», «6 часов»;
  - возраст: «**11 12 лет**»;
  - время приезда: «приедут **либо 10** либо 14 утра»;
  - «1 **5** игры» — обрывок другого числа.
  Берём число рядом с `человек/участник/гость/детей/ребят` (это основной сигнал), а без него — только
  со словами заказчика: `нас`, `у нас`, `будет`, `планируем`, `примерно`, `около`, `где то`, `типа`.
  При нескольких кандидатах — первое названное (не максимальное).
- Результат на реальных звонках 08.10.2026: **№869 «2» → 30**, **№870 «16» → 30**; на всех 40 размеченных
  звонках меняются 11 значений (29 без изменений, см. «Переразметка»).

Порядок типов: `недозвон` → `нецелевой` → `школьная_группа` → `детский` → `корпоратив` →
`праздник_взрослые` → `просто_игра` → `непонятно`.

## Что берём в работу

`TAGGER_LOOKBACK_HOURS` (на сервере — 24) — окно по `call_datetime`. Архив не переразмечается,
старые теги не переписываются: берём только записи без `metadata.tags`.

## Установка на сервере (Beget, 159.194.225.230)

```bash
python3 -m venv /opt/zcminiapp/.venv-tagger
/opt/zcminiapp/.venv-tagger/bin/pip install -r requirements-tagger.txt
# модель кладём в /opt/zcminiapp/models (качается с HuggingFace при первом запуске)
```

Служба — `systemd`, unit `zc-tagger` (образец — в логе деплоя 13.13 и в `/etc/systemd/system/`):
`EnvironmentFile=/opt/zcminiapp/.env.worker`, `ExecStart=/opt/zcminiapp/.venv-tagger/bin/python -m calls_tagger.main`,
`Restart=always`, `MemoryMax=1300M` (чтобы неудачная расшифровка не утащила за собой воркер).
Переменные: `TAGGER_MODEL=small`, `TAGGER_MODEL_DIR=/opt/zcminiapp/models`,
`TAGGER_HEALTH_PORT=8082`, `TAGGER_INTERVAL_SECONDS=300`, `TAGGER_LOOKBACK_HOURS=24`.

## Замеры (09–10.10.2026, 2 CPU)

Расшифровка записи 174 с занимает 40–48 с (≈4× реального времени), пик памяти процесса —
684 МБ на модели `small`, 580 МБ на `base`; сама модель на диске — 464 МБ (`small`).
В день приходит 3–13 звонков (≈15 минут аудио) — это 3–4 минуты процессора.
Из-за памяти служба не влезает на VPS 1 ГБ: нужен сервер от 2 ГБ (Prime 2/2, 810 ₽/мес).
