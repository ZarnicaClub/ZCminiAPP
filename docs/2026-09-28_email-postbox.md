# Отчёт об изменении — письма клиентам через Yandex Cloud Postbox

- **Дата:** 28.09.2026
- **Сервис:** `orders-webhook` (отправка писем внутри общего приложения `ZCminiApp`)
- **Зачем:** SMTP с Timeweb App Platform физически не работает — у приложения закрыты исходящие
  почтовые порты (`blocked_ports: 25/465/587/2525`). Итог на 25.09.2026: из 64 оплаченных заказов
  **не ушло ни одного письма** (у всех пусто `orders.confirmation_sent_at`).
- **Что сделано:** транспорт заменён на HTTP API Yandex Cloud Postbox (совместим с Amazon SESv2,
  порт 443). Шаблон письма и вся логика вокруг остались прежними.

## Что изменено

| Файл | Что |
|---|---|
| `shared/mailer.py` | `_smtp_send` → `_postbox_send` (boto3 sesv2, env `POSTBOX_*`); `smtp_enabled()` → `email_enabled()`; `log_smtp_config()` → `log_mail_config()`; отправитель `noreply@send.zarnicaclub.ru`, `Reply-To: info@zarnicaclub.ru`; заголовки From/Subject теперь через `Header(...).encode()` (RFC 2047) |
| `orders_webhook/service.py` | импорт `email_enabled` вместо `smtp_enabled` |
| `orders_webhook/app.py` | `log_mail_config()` на старте вместо `log_smtp_config()` |
| `.env.example`, `docker-compose.yml`, `docker/docker-compose.dev-3services.yml` | секция SMTP → POSTBOX |
| `tests/test_mailer.py` | новый файл: 7 тестов (маппинг полей, структура письма, raw-запрос, feature-флаг) |

Письмо уходит **raw MIME** (а не Simple), потому что в шаблоне hero-картинка подключена как
`cid:zarnica-hero` — Simple-контент вложения не умеет. Новых зависимостей нет: boto3 уже
использовался для S3.

## Переменные окружения (App Platform)

Удалить/оставить неиспользуемыми `SMTP_*`, добавить:

```
POSTBOX_KEY_ID     — идентификатор статического ключа сервисного аккаунта postbox-user
POSTBOX_SECRET     — секрет ключа
POSTBOX_REGION     — ru-central1 (по умолчанию)
POSTBOX_ENDPOINT   — https://postbox.cloud.yandex.net (по умолчанию)
```

Если `POSTBOX_KEY_ID`/`POSTBOX_SECRET` не заданы — отправка выключена (feature-флаг), письма не
уходят, вебхук работает как обычно.

- `pytest -q` в `zcminiapp` → **31 passed** (24 прежних + 7 новых).

  hero-картинка на месте (`Content-ID: <zarnica-hero>`, 833 КБ).

## Грабли (стоили времени, не повторять)

1. **`str(Header("ЗарницаКлаб", "utf-8"))` возвращает НЕкодированную строку.** С ней в заголовке
   уходит сырой UTF-8, и Postbox отвечает `BadRequestException: email address parse failed (From)`.
   Нужен `.encode()`: `Header(...).encode()` → `=?utf-8?b?...?=`. Проверено: с `.encode()` письмо
   принимается, с `str()` — нет. ASCII-имя тоже проходит, русское без кодирования — нет.
2. **`Header(s, charset, "base64")` — ошибка**: третий позиционный аргумент это `maxlinelen`, а не
   кодировка; при передаче строки падает `TypeError` внутри `header_encode_lines`.
3. Отправка только адресом (`From: noreply@send.zarnicaclub.ru`) Postbox тоже принимает — если
   когда-нибудь понадобится убрать имя, это допустимый путь.

## Откат

- Выключить без правки кода: убрать `POSTBOX_KEY_ID`/`POSTBOX_SECRET` из окружения.
- Откат кода: `git revert` коммита в `main` (или восстановить `shared/mailer.py` из предыдущей ревизии).

## Правка вёрстки карточек «Ваша игра» / «Ваш заказ» (28.09.2026)

Замечание Артёма по тестовому письму: блоки должны быть одного размера, а в левом блоке длинный
тариф («Пейнтбол Стандарт Плюс») наезжал на разделитель и ломал строку «Размещение».

Что сделано в `shared/email/email.html`:
- строки внутри карточки собраны **вложенными таблицами «подпись | значение»** (подпись 42 %, значение
  с `text-align:right`) вместо `float:right` в одном div — float не переносит длинное значение само,
  оно уезжало под подпись и наезжало на границу;
- карточкам задана **одинаковая высота**: `height="300"`/`style="height:300px"` на ячейках 50 % и
  `height="100%"` на внутренней таблице (flex/grid почтовые клиенты не понимают);
- у последней строки левой карточки граница снизу убрана, у остальных `border-bottom` — линия
  по-прежнему идёт через всю карточку.

Проверка: письмо рендерится в файл (`cid:zarnica-hero` заменяется на `data:`-URL) и открывается
в headless Chrome — у обеих карточек `getBoundingClientRect()` даёт одинаковые width/height/top
(900/600/390 px: обе 264 px, переполнения нет). Скриншот области карточек — `letter_cards_264px.png`.

Вторая правка по замечаниям Артёма (там же, 28.09.2026):
- высота карточек **300 → 264** (строки раздвинуты отступом 14 px, чтобы пустое место не копилось снизу);
- **тема письма**: `EMAIL_SUBJECT` = «Ваше бронирование подтверждено» (в списке писем под отправителем
  «ЗарницаКлаб» больше нет повтора названия клуба);
- **подвал**: из шаблона убрана подпись «Telegram / WhatsApp:», которая дублировала саму заглушку —
  строка выводится как `{{club_messenger}}`; когда появится реальный контакт, значение станет
  «Telegram: @zarnicaclub»;
- `alt` у hero-картинки приведён к новой теме («Ваше бронирование подтверждено»).

## Выкат и рассылка (28.09.2026 — выполнено)

**Выкат.** Пуш `main` (5 коммитов) → GitHub Actions: тесты пройдены, образ собран и залит в Docker Hub
(`:latest` и `:<sha коммита>`) → деплой приложения `ZCminiApp` (id 258415).

Грабли, найденные на этом выкате (стоили двух лишних перезапусков):
1. **`POST /apps/{id}/deploy` больше не работает:** с пустым телом → `400 commit_sha should not be null`,
   с `commit_sha` → `500 {response_id}` (ошибка на стороне Timeweb). Прежний воркфлоу дёргал именно его,
   а шаг стоял с `continue-on-error` — поэтому деплой **молча не запускался**.
2. **Платформа НЕ перетягивает образ, если тег не изменился.** Правка переменных в панели (и `PATCH`
   с тем же `latest`) перезапускает контейнер со **старым** кодом: в логе после выката оставалась прежняя
   строка `SMTP: выключен (SMTP_HOST не задан)`, хотя в Docker Hub уже лежал новый образ.
3. **Рабочий способ:** `PATCH /apps/{id}` с `{"docker_image": "...", "docker_image_tag": "<sha коммита>"}` —
   новый неизменяемый тег, платформа обязана скачать свежий образ. Воркфлоу переписан на этот вариант.
4. **Признак, что выкат реально доехал** — строка в логе приложения: было `SMTP: выключен …`,
   стало `письма: вкл | отправитель=noreply@send.zarnicaclub.ru reply-to=info@zarnicaclub.ru |
   postbox=… (ru-central1, ipv4=[158.160.78.193]) | ключ …z48h | шаблон=True картинка=True`.
   Проверять именно её, а не факт «деплой success» — деплой может быть успешным со старым образом.
5. Образ проверяется без Docker-демона (`container-image-inspection`, `scripts/pull_image_files.py`,
   `--want app/shared/`) — так подтвердили, что в Docker Hub лежит именно новый код.

**Что видно после выката:** `/healthz/deep` → `database: ok, s3: ok`; `/` (мини-апп) → 200;
`/api/orders` без `X-Telegram-Init-Data` → 401; вебхуки с неверным секретом → 403; в логе — строка про почту.
