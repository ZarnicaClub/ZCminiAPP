# Процедура отката (rollback)

## Принцип
Текущее рабочее приложение лежит в архиве `zarnica-crm-v11.11-reports-clean`.
Откат = вернуть старый образ и старую схему. Источник данных для восстановления:
`newCRM/default_db.sql` (DDL), `newCRM/orders.csv`, `newCRM/calls.csv` (данные).

## 1. Откат приложения (быстрый)
1. В Timeweb App Platform остановить/удалить новые сервисы
   (`orders-webhook`, `calls-worker`, `crm-api`).
2. Передеплоить старый монолит `zarnica-crm-v11.11-reports-clean` из архива
   (тот же Docker Hub-образ / исходник).
3. Вернуть URL веб-хука Tilda на старый endpoint.

## 2. Откат схемы БД
Миграции применяются **сначала на staging, затем на prod** (решение заказчика).
Поэтому до применения к prod всегда есть проверенная копия.

1. Если миграция уже применена к prod и нужно откатить:
   - восстановить `orders`/`calls` из резервных копий (pg_dump / CSV);
   - выполнить `alembic downgrade` до базлайна (если миграция обратима),
     либо восстановить дамп `default_db.sql`.
2. `order_items` удаляется отдельной миграцией (этап 3); до этого момента
   таблица остаётся на месте, поэтому откат до удаления тривиален.

## 3. S3
- Существующие MP3 во время миграции НЕ перезаливаются и НЕ переименовываются.
- Новые объекты пишутся аддитивно (контентно-адресуемые ключи) — удаление
  нового кода не удаляет старые объекты.

## 4. Контрольные точки
- git-тег `v11.11-clean` = исходное состояние (этап 0).
- После каждого этапа — тег `stage-N-pass`; к нему можно откатиться.
