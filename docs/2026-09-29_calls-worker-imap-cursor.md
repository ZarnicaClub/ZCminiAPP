# calls-worker: забираем только новое из почты (закладка по UID)

**Дата:** 29.09.2026
**Сервис:** `calls-worker` (монорепо `ZarnicaClub/ZCminiAPP`), версия **13.07**
**Среда:** VPS Beget, `159.194.225.230` (там Docker не используется, код в `/opt/zcminiapp`, systemd `zc-worker`)

## Что было не так

Цикл раз в 5 минут работал по «окну»: каждый раз искал письма за последние 24 часа и **скачивал тела писем целиком вместе с MP3** — в том числе тех, что уже разобраны. На 6 письмах в окне это ~900 повторных скачиваний в сутки. Яндекс на это отвечал троттлингом: `imaplib.IMAP4.abort: command: UID => problems with connection`, обрыв ронял весь цикл. Плюс `/status` врал: письма-дубликаты падали в счётчик `unmatched`, а `processed` рос от всех писем окна каждый цикл.

## Что стало

- **Закладка (курсор) по UID.** Хранится в файле `var/calls_worker_state.json` рядом с кодом: `last_uid`, `uidvalidity` (отпечаток ящика) и время записи. Записи в БД, миграций и новых зависимостей нет.
- **Поиск только нового:** `UID SEARCH UID <last+1>:*` вместо `SINCE` на каждой итерации. По стандарту `n:*` отдаёт минимум последнее письмо ящика, поэтому всё, что не больше закладки, отсекается отдельно.
- **Проверка дублей до скачивания.** `email_id` в таблице `calls` — это и есть UID письма, поэтому «какие уже разобраны» видно из поиска: тела таких писем не качаются вообще.
- **Страховка от простоя.** Нет закладки, файл битый или сменился `UIDVALIDITY` (ящик переиндексировали) → проход по дате (`SINCE`), причём окно расширяется до времени последнего разбора с запасом в сутки и не глубже 30 суток.
- **Закладка двигается отдельно от разбора.** Письма «не той структуры» (нет MP3 или их несколько) и битые MP3 закладку пропускают — иначе качались бы вечно. А сбой скачивания (сеть, БД, S3) закладку **не** двигает: такое письмо повторяется в следующем цикле.
- **Назад закладка не едет** — кроме смены `UIDVALIDITY`, когда старый номер к новому ящику отношения не имеет.
- **Честные счётчики.** `processed` — только письма, взятые в разбор; дубликаты — отдельный `duplicates`; `unmatched` — только «разобрали, заказ по телефону не найден»; письма не той структуры — `malformed`; `errors` остаётся для настоящих сбоев. Добавлены `mode`, `last_uid`, `selected`, `downloaded`, `skipped` и блок `last_cycle` с цифрами последнего цикла.
- **Строка лога цикла:** `цикл за N с (cursor): в выборке 6, к скачиванию 0, скачано 0, уже было 6, сохранено 0, привязано 0, без пары 0, брак 0, ошибок 0, закладка 14845`.

## Файлы

- `calls_worker/state.py` — новый модуль: чтение/запись закладки (атомарно, через временный файл), путь из `WORKER_STATE_FILE` или `var/calls_worker_state.json`.
- `calls_worker/imap.py` — `fetch_new_messages()` возвращает `Selection` (режим, UID в выборке, что качать, сбои, UIDVALIDITY, всего в папке), добавлены `known_email_ids()` и `advance_cursor()`.
- `calls_worker/service.py` — цикл работает по `Selection`, новые счётчики, двигает закладку.
- `calls_worker/main.py` — в стартовой строке путь к закладке, в логе цикла цифры из `last_cycle`.
- `tests/test_calls_worker_cursor.py` — 13 новых тестов (ящик-двойник, файл закладки): 66 тестов всего.
- `VERSION` → 13.07, `APP_VERSION` в `app/main.py` → 13.07.

Поведение, которое не менялось: интервал 300 с, окно 24 ч, дедупликация по `email_id` и `sha256`, заливка в S3, запись в `calls`, привязка по телефону, advisory-lock от параллельных прогонов.

## Проверки

- `pytest -q` — **66 тестов, все зелёные** (было 53).
- Сухой прогон на живом ящике (выборка без скачивания и без записи в `calls`):
  - ящик `CALLS` — 14 519 писем, `UIDVALIDITY` 1582032615;
  - прогон 1 (закладки нет): в выборке 6 писем, из них уже в базе 6, **к скачиванию 0** (было бы 6 тел с MP3);
  - прогон 2 (по закладке): в выборке 0, к скачиванию 0, файл закладки не менялся.
- На боевом сервере сверены md5 всех файлов `calls_worker/*` — совпали с репозиторием, «своих» правок на сервере не было.

## Откат

Бэкап перед выкатом: `cp -a /opt/zcminiapp/calls_worker /opt/zcminiapp/calls_worker.bak-<дата>` и копия `.env.worker`.
Возврат: восстановить файлы из бэкапа, `systemctl restart zc-worker`, файл закладки можно удалить (`rm /opt/zcminiapp/var/calls_worker_state.json`) — воркер вернётся к работе по окну.
